# v2.14 (V214.md 4.3): the data tables whose strings are shown to players. `node tools/i18n_extract.js --en` puts exactly these
# strings into game/i18n/en.json, keyed data.<table lowercased>.<path> (the path rule of the extractor's dataPath:
# object rows by their id / key / k / n / name, maps by property, plain arrays by index, call rows by their first argument, each argument by
# the builder's parameter name: treasures.acorn_cap.txt for TR('Acorn Cap', ..., txt)).
# One line per table: NAME, then the fields that are text, or * for every string in the table. A field is the path without its
# row id (`note` for food.wild_berries.note, `1` for acts.feed.1, `ask.*` for breed_pers.shiba.ask.0; `*` is any one part),
# or the whole path for a table that is one object (`from` for hw_letter.from). `@key:n`: a map keyed by the English name
# also gives that name as <table>.<tid(name)>.n (hm_decor.giant_crayon_box.n). The display site looks each one up: tdata('food.' + tid(f.n) + '.note', f.note).
# Not listed on purpose: dog-name lists (SP, FALLBACK_DOGS name, PUP_NAMES, RESCUE_NAMES, SR_NAMES, DC_PET_NAMES, DC_FAKE),
# lists of item names that are save values (RAINCOATS, WARM_WEAR, FETCH_TOYS, SNACKS, LOOT16, FS_COSTUMES, WN_OUTS,
# TK_SNACKS, TK_SOUVENIRS, BL_BALLS, BL_TOYS, SIG_COMBO, SPOT_RULES, mods/toys.js TOYS: the item's own row gives its name),
# gene symbols, chord names, the painted art words and the art fallbacks (FS_FB, HW_FB). Tables of functions (CARD_LINES,
# NY_PUP_LINES) become tt() messages in their files. NAME@file-stem limits a line to that file's table of the name.
# A camelCase name keys as snake case (jpPlaceLines -> data.jp_place_lines.shiba); a table that is one string (HW_PLUM) is data.<table>.
# A value chosen by a condition (`a ? 'Tide pool' : 'Puddle'`) gives two keys: <path> and <path>_2 (the else branch).
