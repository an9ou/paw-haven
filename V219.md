# V2.19 "Friends first": design contract

Goal (owner's growth plan, 26 Oct 2026, plan item 1; started 1 Nov 2026): friend codes, yard visits, gifts and a shared walk. Friends are the
strongest reason players come back, and every invite brings a new player for free.

Owner's choices (1 Nov 2026):
- The shared walk is **async**: a friend's dog joins your walk, drawn from their latest snapshot. You don't need to be online together.
- A yard visit shows a **read-only snapshot** of the friend's yard.
- **No free text anywhere**: only preset kind lines and list words.
- The coding is done by **Cursor**, from GitHub issues, one per part. The Game Manager (Claude) designs, draws the art, translates, reviews
  every PR against this contract and the game's rules, deploys the Worker and ships the release.
- **Special update**: v2.19 goes live only on the owner's go-ahead and launch date (CLAUDE.md).

Out of scope for v2.19 (plan items 5 and 6, later):
- Playdates with friends' dogs.
- The friend board in town.
- Gifting toys, clothes or coins.
- Any live or realtime play.

## 0. Rules that every part keeps
- **No typed text leaves the device.** A player's friend name is two words picked from the Dog Card lists (`DC_WORDS_A` × `DC_WORDS_B`,
  e.g. "Sunny Biscuit"). Dogs are shown by their card look, and a dog's name only as the Dog Card `n` index (the pet-name list or the breed word).
  Typed dog names never go to the server. Notes are picked from `FR_NOTES` (section 4). There is no search and no directory: you can add someone
  only by their code or invite link. This also covers the plan's under-13 rule for everyone, without asking anyone's age.
- **The user id never leaves the Worker.** Other players see only a random public id (`fid`, 22 chars, like a Dog Card id) and the friend code.
- **Nothing personal is shown**: no email, no location, no times beyond "today" or "this week".
- **Nothing bad ever happens.** You can't lose anything to a friend. Remove and block are quiet, and the other side is never told.
- Save migration is **additive** in `migrate()` (`v219Fields(s)`): new fields get defaults, `v` stays 1, and old saves load.
- Friends need the cloud. They are **off** on the claude.ai artifact (`clArtifact()`) and under the test harness, unless the test sets
  `window.__pawCloudMock` or `prefs.frTest`. Offline, the Friends sheet says "Friends need an internet connection. Your dog is happy at home."
  and shows the cached list.
- Guests (no email) can have a code and friends. The sheet shows the existing "make an account so you don't lose your save" nudge once.
- Words: never "breed" as a verb, "stud" or "sell" for dogs. English through `tt('fr.*', '...')`. Claude translates all 11 languages in one
  batch at the end, so Cursor writes English only.
- Phones first: everything fits at 390x844 and 360x740, taps are 44 px or more, nothing hides under the phone bar (Care / Walk / Map / More).
- Economy: walks stay the main income. Friends add at most **20 coins a day** (section 6) and a little Bond.

## 1. Server (Cloudflare Worker `pawhaven-api`, D1 `pawhaven`)
All in `cloudflare/worker.js` and `cloudflare/schema.sql`. The schema is re-applied on deploy, so use `create table if not exists`.
Every route needs the bearer token (guest or email user). Days are Japan days (`YYYY-MM-DD`, JST), as `paws` uses them.

Tables:
- `friend_ids(user_id pk, fid unique, code unique, name_a int, name_b int, created_at, code_at)`. The code is `DOG-` plus 5 characters from
  `ABCDEFGHJKMNPQRSTUVWXYZ23456789`, about 28.6 million codes. "New code" replaces it, and the old code stops working.
- `friends(user_id, friend_id, created_at, primary key (user_id, friend_id))`: two rows per friendship. At most 50 friends each.
- `friend_blocks(user_id, blocked_id, primary key (user_id, blocked_id))`.
- `yards(user_id pk, data text, updated_at)`: the snapshot (section 2), 16 KB at most.
- `friend_events(id integer primary key, to_id, from_id, kind, data text, day, created_at, claimed_at)`:
  - `kind` is one of `pet | note | gift | walk`.
  - Unique on `(from_id, to_id, kind, day)` for pet, note and walk; unique on `(from_id, kind, day)` for gift (1 gift a day in all).
  - Index on `(to_id, claimed_at)`.
  - Events older than 30 days are deleted lazily on any inbox read.

Routes (JSON in and out, errors as `{ error: 'code' }`):

| Route | Does | Limits |
| --- | --- | --- |
| `GET /friends` | `{ me: { fid, code, name:[a,b] } \| null, friends: [{ fid, name:[a,b], dogs: [up to 5 card dogs], seen: 'today'\|'week'\|'older', sent: { pet, note, gift, walk } (sent to them today) }] }` | 120/h |
| `POST /friends/me` `{ name:[a,b] }` | creates or renames my friend id and code; returns `me` | 20/h |
| `POST /friends/code/new` | a new code for me; the old one stops working | 5/day |
| `POST /friends/add` `{ code }` | adds both ways at once (sharing your code is the consent). Errors: `not_found`, `self`, `full` (50), `blocked` (either side, answered as `not_found`), `already` | 10/h per user and 30/h per IP; misses count too |
| `POST /friends/remove` `{ fid }` | removes both rows and the unclaimed events between the two | 30/h |
| `POST /friends/block` `{ fid }` | remove, plus a block row; they can't add you again with any code | 30/h |
| `PUT /friends/yard` `{ yard }` | validates and stores my snapshot (section 2) | 30/h |
| `GET /friends/yard?fid=` | that friend's snapshot; only for friends, otherwise `not_found` | 120/h |
| `POST /friends/send` `{ fid, kind, data }` | records one event (sections 3 to 6); `limit` when today's is used up; only to friends | 60/h |
| `GET /friends/inbox` | my unclaimed events, oldest first, at most 30 | 120/h |
| `POST /friends/inbox/claim` `{ ids:[] }` | marks them claimed; idempotent | 120/h |

The Worker validates every index against append-only limits, like `DC_LIM`:
- the name words;
- `FR_NOTES` (12);
- the gift item list `FR_GIFTS` (section 5);
- `FR_DECOR` (section 2);
- `FR_HOUSES`;
- the card dog fields, using the Dog Card checks.

Anything out of range is rejected with `bad`. Tests: extend `game/test_worker.js` (Miniflare, local D1) to cover every route, every limit,
block, remove, the gift-a-day rule and that no `user_id` or email ever appears in a response.

## 2. The yard snapshot
The client builds it from the save and `PUT`s it at most once every 10 minutes, after a cloud push (`22b_cloud.js` `clOnSaved` path), and only
when the player has a friend id. Shape, all indices:

```
{ v: 1, name: [a, b], house: <FR_HOUSES index>, season: 'spring'|'summer'|'autumn'|'winter',
  dogs: [ up to 5 Dog Card dogs { b, c, o, a, s, sp, n } — the leader first ],
  decor: [ up to 40 { i: <FR_DECOR index>, x, y } ]  (yard positions as saved, rounded) }
```

- `FR_DECOR` and `FR_HOUSES` are explicit **append-only** arrays of item names in `game/src/50_friends.js` (new; add it to `game/src/ORDER.txt` after `49c_news.js`). They start with every yard decor item
  and house in `HM_DECOR` / `HOUSES` today, the Winter Market ones included. New items are added at the end, never inserted or reordered.
  The Worker only knows each array's length.
- Dogs use `dcDogOf` / `dcCoat` from `40_dogcards.js`, the same as Dog Cards (double merle is already rejected there).

## 3. Friend codes and the Friends sheet (part 2)
- **Where:** a "Friends" button in the phone More tray and in the desktop "..." menu, next to Daily missions. A small badge counts unclaimed inbox
  items.
- **First open:** "Pick your friend name". Two crayon wheels of words, plus a Random button and a preview ("Sunny Biscuit"). If the player has
  a Dog Card, its name is the default. Then the card appears.
- **My card:** the friend name, the code in big crayon letters (`DOG-4K7PM`), a QR code of the invite link, and these buttons:
  - **Share invite**: `navigator.share` with the link, falling back to copying it to the clipboard with a toast "Invite link copied".
  - **Copy code**.
  - **New code**, behind a confirm: "Your old code will stop working. Friends you already have stay."
  - The invite link is `https://doodledoggo.app/f/DOG-4K7PM`.
- **Add a friend:** a code box with `DOG-` fixed and 5 character boxes (uppercase, no 0/O/1/I), and an Add button. Toasts:
  - "Sunny Biscuit is your friend now!" (hearts on your dog)
  - "We couldn't find that code. Check the letters?"
  - "That's you! Share your code with a friend."
  - "You have 50 friends, the most for now."
- **Friend list:** one row per friend, sorted by who you have sent the least to today, then by name. Each row shows:
  - the leader dog's crayon head;
  - the friend name;
  - "Visit" and "Gift" buttons;
  - three tiny doodles that fill in once you have petted, noted and gifted today;
  - a "..." menu with "Remove friend" and "Block". Block's confirm says "They won't be able to add you again." Both are quiet.
- **Opened from an invite:** with `?friend=DOG-XXXXX` in the URL (or `#friend=`), the game shows the add card pre-filled after the title. A new
  player sees it right after adoption, never before the first-day guide.
- **QR:** a small MIT-licensed QR encoder vendored into `mods/qr.js` (licence header kept), drawn as SVG squares in pencil colour, with no
  network calls.
- **Inbox polling:** on open, on focus (at most every 60 s) and when the Friends sheet opens. Claimed events become letters (sections 4 to 6), and
  the badge counts unclaimed ones.

## 4. Yard visits, pets and paw-print notes (part 3)
- **Visit** opens the friend's yard as a read-only place, `cur.mode = 'fryard'`. The scene shows:
  - the yard art with their house, their decor at their positions and the season from their snapshot;
  - their dogs roaming, drawn as `dcDraw` draws Dog Card visitors;
  - a chip "Sunny Biscuit's yard";
  - "Leave a paw print" and "Go home" buttons.
  Your own dog comes along and roams too. The garden, mailbox, missions, shop doors and anything else that changes a save are hidden or inert.
- **Pet:** tapping a friend's dog shows hearts and a happy pose (`say` a line from the dog's personality).
  - The first pet per friend per day sends a `pet` event.
  - Your leader gets **+1 Bond**, for at most 5 friends a day.
  - The friend's leader gets **+1 Bond** when they claim it, for at most 5 claimed pets a day.
  - The friend's letter reads "Sunny Biscuit visited and petted Pip. +1 Bond", and several pets on one day go into one letter.
- **Paw-print note:** one per friend per day. Pick one of `FR_NOTES`, a paw stamp appears on the yard path, and the friend gets a postcard letter
  with your friend name, the line and a paw doodle. `FR_NOTES` is an append-only list:
  1. Your dog is so fluffy!
  2. Thanks for the gift!
  3. Happy walk day!
  4. Your yard looks lovely!
  5. Woof! (That means hello.)
  6. See you tomorrow!
  7. What a nice outfit!
  8. Sending a big sniff!
  9. Have a cosy day!
  10. Your garden is growing!
  11. Best buddies!
  12. Good dog, good day!
- A friend with no snapshot yet: "Sunny Biscuit's yard is still being tidied. Try again later."

## 5. Gifts (part 4)
- **One gift a day in all** (not per friend), from your bag, of **consumables only**: snacks and treats, seed packets, and flowers or veg from the
  garden. `FR_GIFTS` is the append-only list of giftable item names. It starts with every such item in `FOOD` and the garden and seed tables that is
  safe for dogs. Festive treats are included: they are gifts, not shop stock.
- **Gift sheet:** opened from a friend row or from a "Send a gift" button during a visit. It shows a grid of the giftable items you have, with counts. Pick one, then confirm:
  "Send 1 Pumpkin Biscuit to Sunny Biscuit?". The item leaves your bag only after the server answers `ok`. The send has a crayon wrap animation
  and the toast "Your gift is on its way!".
- **Receiving:** a mailbox gift letter with the friend name and a wrapped-gift doodle. It reuses the existing gift flow (`mailPush`
  `{ kind: 'gift', gift: { cat, id, n: 1 } }`, Collect with `mbCollect`). At most 5 gifts are turned into letters a day; the rest wait for
  tomorrow.
- No coins, toys, clothes, dogs or puppies can be given. Dogs can never be given or traded.

## 6. Walk together (part 5)
- The walk route picker gets a row "Walk with a friend's dog". It lists your friends' dogs from their snapshots (cached, fetched once a day). Pick
  one, or none, which is the default.
- The guest dog joins `o.pack` (`18_mod_walk_toys.js` → `mods/walkrun.js`) as one more follower. It is drawn from its card look, wears a small
  friend ribbon and keeps to the pack's maximum (it takes one follower slot). The guest is cosmetic in the runner: no stats, no needs.
- **When the walk ends:**
  - You get **+10 coins** for each friend walk, for at most 2 friend walks a day. That is the 20-coin daily cap, before `BOOST`, kept in
    `S.fr.walkDay` and `S.fr.walks`.
  - A `walk` event goes to the friend: `data: { t?, dog, mine }`. `t` is the walk's treasure if there was one (`rollTreasure` result, as an
    item index in `FR_GIFTS`), `dog` is the index of their dog in their snapshot, and `mine` is your leader as a card dog, for the letter's
    picture.
  - The friend's letter: "Pip went for a walk with Sunny Biscuit's Mochi and found a pine cone for you!". The treasure comes as a gift to
    Collect, or there is just the letter. At most 3 walk letters a day.
- One walk event per friend per day; a later walk with the same friend that day is fine but sends nothing.

## 7. Invite link and privacy (part 6)
- **doodledoggo.app `/f/DOG-XXXXX`** (site Worker `doodle-doggo`, `tools/cf_site.js`, `site/`): a small crayon page that says
  "A friend invited you to Doodle Doggo!". It shows the code big, with two buttons:
  - "Play here": `/play/?friend=DOG-XXXXX`.
  - "Play on itch.io": the itch page link. Below it: "itch.io can't pass the code along, so type it in the game: More → Friends → Add a friend."
  The page asks the API nothing. It is in all 11 languages through the site's language system; Cursor writes the English and Claude translates.
- **`/play/`** forwards `?friend=` into the game's URL, as it already does with `lang`.
- **Privacy** (`site/privacy.html` and `docs/itch/PRIVACY.md`, English; Claude translates): a "Friends" section. It covers:
  - what friends can see: your friend name, your dogs' looks, your yard and decorations;
  - what is stored: your friends list, blocks, the yard snapshot, and pets, notes, gifts and walks for 30 days;
  - that there is no free text;
  - how to remove or block;
  - that turning Friends off deletes your code, list and snapshot. "Leave Friends" sits in Settings, behind a confirm, and needs a
    `POST /friends/leave` route (part 1: deletes my friend id, friends both ways, blocks I made, my yard and my events).

## 8. Save fields (`v219Fields`)
`S.fr = { on: false, name: null, code: null, fid: null, cache: { at: 0, friends: [] }, yards: {}, day: '', pets: 0, gotPets: 0, notes: 0, gift: false,
gotGifts: 0, walkDay: '', walks: 0, gotWalks: 0, guest: null }`.
- `S.fr.guest` is the chosen friend dog for the next walk.
- The daily counters reset on a new `localISO()` Japan day.
- None of these fields go into the yard snapshot.
- Cloud sync carries `S.fr` like the rest of the save.

## 9. Art (Claude, before part 2)
Art lives in `world/pawart_world_b.js` as `PA.FRIENDS.*`, with every fill inside its outline:
- `PA.FRIENDS.badge()`: two crayon dog heads touching noses, for the menu button.
- `PA.FRIENDS.card(code)`: the code card frame with room for the QR.
- `PA.FRIENDS.wrap(n)`: a wrapped gift in 3 paper patterns.
- `PA.FRIENDS.paw()`: the paw-print stamp for the path and the note letters.
- `PA.FRIENDS.ribbon()`: the guest dog's friend ribbon.
- `PA.FRIENDS.wheel()`: the name wheel frame.

Cursor only calls them. If one is missing, it falls back to an existing icon and leaves a `// TODO art` comment.
