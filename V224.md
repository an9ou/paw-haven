# v2.24 "Kind shop" (contract; not released)

The owner's decisions: `docs/design/kind-shop.md` (3 Nov 2026, and the list of 8 Nov 2026). Economy numbers: `docs/design/economy-review.md`,
`tools/econ/journey.md`. **This is a big release:** it goes to `main` only after the owner gives the go-ahead and a launch date (CLAUDE.md, the
special-update rule; the 5-minute default does not apply). Aim: early December 2026. Build branch `claude/kind-shop`, in parts, at most 2
subagents at once; three reviews (code, phone, art). Gate: `SHOP_LIVE = false` until launch (like `MS2_LIVE`, `FR_LIVE`).
Suite: `v224_shop`. Save stays `v: 1`; new fields are added in `migrate()` with defaults.

## 0. The shop rule (replaces the Growth Plan's "never coins-for-power")

"We sell coins and looks, never dogs, Bond, welfare or chances. No loot boxes or random paid rewards, and the game is complete without paying."
- Sparkle stays free and is never sold, for cash or coins (design rule).
- Every paid item has a fixed, shown content. Every purchase has a confirm step (owner, 8 Nov: the confirm step only, no grown-up check, no cap).
- The v2.16 calendar line "no paid items" is reworded in all 12 languages.
- No rewarded ads in this release (8 Nov: they come later, on doodledoggo.app/play/ only; section 9).

## 4. Payments (Stripe Managed Payments, owner is the Hong Kong seller)
Stripe is the merchant of record and handles sales tax and VAT (owner, 8 Nov). Stripe account already open (8 Nov).
- Worker routes (`cloudflare/worker.js`, built in part 3). Every one answers 503 `{ error: 'shop_closed' }` while `STRIPE_KEY` is unset
  (the webhook also needs `STRIPE_WEBHOOK_SECRET`), so the Worker can be deployed before the keys exist.
  - `GET /shop/catalog` (no session): `{ items: [{ id, usd, once, on }] }`, `usd` in US cents, `on` = a Stripe price is set. The prices and
    once flags live in `SHOP_ITEMS` in the Worker and the Stripe price ids in `SHOP_PRICES`; the game never sends a price. Price ids are not shown.
  - `POST /shop/checkout` (email accounts only: 403 `no_account` for a guest; 20 an hour): `{ item }` → a Checkout Session by `fetch` to
    `api.stripe.com/v1/checkout/sessions`, form encoded, no SDK: `mode=payment`, the item's price, quantity 1, `managed_payments[enabled]=true`
    (Stripe's Managed Payments set-up guide, docs.stripe.com/payments/managed-payments/set-up; needs API version `2025-03-31.basil` or later),
    `client_reference_id` = user id, `metadata[item]`, `metadata[user]`, `customer_email`, success / cancel URLs `https://doodledoggo.app/thanks?ok=1`
    / `?ok=0`. Returns `{ url }`. 409 `owned` for a one-time item the account owns and has not had refunded (the Comfort Kit covers its three
    tools, and all three tools cover the Kit). 400 `bad_item`; 503 `shop_closed` for an item with no price id; 503 `busy` if Stripe says no.
  - `POST /shop/webhook` (no session, no CORS: Stripe calls it server to server). Handled in `route()` before any JSON parsing: the raw body
    is checked against `Stripe-Signature` (HMAC-SHA256 of `${t}.${raw}` with `STRIPE_WEBHOOK_SECRET`, constant-time compare, any `v1`,
    5-minute tolerance both ways). 400 `bad_signature` / `stale`. `checkout.session.completed` and `checkout.session.async_payment_succeeded`
    with `payment_status: 'paid'` insert the purchase, idempotent on the session id; `charge.refunded` with `refunded: true` (a full refund)
    sets `refunded_at` by `payment_intent` (a partial refund keeps the item). v2.24.1: when no purchase has that `payment_intent` yet (the refund came
    before its completed event), the Worker looks the session up (`GET /v1/checkout/sessions?payment_intent=`) and writes the purchase already
    refunded; the completed event that follows keeps `refunded_at`. A failed lookup answers 502, so Stripe sends the refund again. Every other event: 200 `{ received: true }`.
  - `GET /shop/owned` (any session, 120 an hour): `{ purchases: [{ id, item, at, refunded }] }`, oldest first.
- D1 table `purchases (id text primary key /* checkout session id */, user_id, item, amount, currency, payment_intent, created_at, refunded_at)`
  with indexes on `user_id` and `payment_intent`, in `cloudflare/schema.sql` (`create table if not exists`, applied by `tools/cf_api_deploy.sh`).
- **Account deletion:** there is no delete-account route (the owner deletes the `users` row by hand, `docs/itch/PRIVACY.md`); `tidy()` then
  deletes that account's purchases like its other rows. Stripe, the merchant of record, keeps its own records for accounting and tax.
- **Founding Friend** (`ff`): the game may send `ff` on a friend yard and a Dog Card (a boolean, checked, then dropped). The Worker sets
  `ff: 1` itself on `GET /friends/yard`, the Dog Card answers (`GET /card`, `PUT /card`, `GET /cards/visit`) when that account has a
  `supporter` purchase that is not refunded. `FR_LIM.houses` is 15 (the Golden Paw Cottage) and `DC_LIM.outfit` 57 (the Golden Name Tag and the
  Tokyo Street six, appended to the game's `DC_OUTFITS`). Deploy this Worker **before** the game release that turns `SHOP_LIVE` on: an
  older Worker refuses house index 14 and outfit indexes 50 and up.
- Worker settings (names only; values never in the repo or chat). Secrets: `STRIPE_KEY` (the secret key, `sk_test_...` first, live at launch),
  `STRIPE_WEBHOOK_SECRET` (the endpoint's `whsec_...`), `SHOP_PRICES` (JSON `{ "supporter": "price_...", ... }`, not secret but kept as a
  secret so `tools/cf_api_deploy.sh` keeps it across deploys). Optional: `STRIPE_VERSION` (a `Stripe-Version` header; else the account's
  default), `SHOP_SUCCESS_URL`, `SHOP_CANCEL_URL`, `SHOP_MANAGED` (`0` turns Managed Payments off, for a test only). Tests only: `STRIPE_FETCH`.
  Owner's steps: `docs/design/kind-shop-stripe-setup.md`.
- The game (`52_kindshop.js`): Pay with Stripe opens a blank tab in the tap itself (`window.open` must run inside the click), asks
  `POST /shop/checkout`, then points the tab at Stripe; on an error it closes the tab and says so kindly (`shop_closed`: "The shop opens soon").
  A blocked pop-up gets a "Pay with Stripe" link sheet instead. It polls `GET /shop/owned` on start and when its tab is shown again (at most
  every 20 s, at once after a checkout) and feeds `ksGrant`; Restore purchases does the same with a toast. Success and cancel pages are small
  pages on doodledoggo.app (`/thanks`, in 12 languages, part 5): "Thank you! Go back to the game tab."

## 5. Granting (save)
- `S.shop = { owned: [], claimed: [], tools: { robo: true, sprinkler: true, bowl: true } }` added in `migrate()`.
- Cash items: on `GET /shop/owned`, each purchase id not in `S.shop.claimed` is granted once (items added to the owned lists, coin packs and
  the Supporter 2,000 coins added to `S.coins`, Gerald's letter posted), then its id goes into `claimed`. A new device that restores gets the
  items, and coin packs it has not claimed in this save (the cloud save carries `claimed`, so a synced save does not get coins twice).
- Refunded purchases: one-time items are taken back (worn items go back to "Nothing"); coins already granted are not taken back.
- Perks read `owns('shop', 'supporter')`, so a refund ends them.
- Coin buys of shop items write the same owned lists, no Worker call.
