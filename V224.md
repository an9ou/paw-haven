## 0. The shop rule (replaces the Growth Plan's "never coins-for-power")

"We sell coins and looks, never dogs, Bond, welfare or chances. No loot boxes or random paid rewards, and the game is complete without paying."
- Sparkle stays free and is never sold, for cash or coins (design rule).
- Every paid item has a fixed, shown content. Every purchase has a confirm step (owner, 8 Nov: the confirm step only, no grown-up check, no cap).
- The v2.16 calendar line "no paid items" is reworded in all 12 languages.
- No rewarded ads in this release (8 Nov: they come later, on doodledoggo.app/play/ only; section 9).

## 4. Payments (Stripe Managed Payments, owner is the Hong Kong seller)
Stripe is the merchant of record and handles sales tax and VAT (owner, 8 Nov). Stripe account already open (8 Nov).
- Worker routes (`cloudflare/worker.js`):
  - `GET /shop/catalog`: ids, USD prices and Stripe price ids (from the Worker config, not the game), so prices change without a game release.
  - `POST /shop/checkout` (auth): `{ item }` → creates a Stripe Checkout Session (Managed Payments; `client_reference_id` = user id,
    `metadata.item`), returns its URL. Refuses `supporter` and one-time items the account owns already.
  - `POST /shop/webhook` (no auth, Stripe signature checked with the webhook secret, raw body): `checkout.session.completed` (and
    `async_payment_succeeded`) writes the purchase; `charge.refunded` marks it refunded. Idempotent on the session id.
  - `GET /shop/owned` (auth): the account's purchases `{ id, item, at, refunded }`.
- D1 table `purchases (id text primary key /* checkout session id */, user_id, item, amount, currency, created_at, refunded_at)`;
  added to `cloudflare/schema.sql`.
- Secrets (Worker, never in the repo or chat): `STRIPE_KEY`, `STRIPE_WEBHOOK_SECRET`; test-mode keys for the test Worker.
- The game opens the Checkout URL in a new tab (itch.io's frame allows `window.open` from a tap). Success and cancel pages are small
  pages on doodledoggo.app (`/thanks`, in 12 languages): "Thank you! Go back to the game tab." The game polls `GET /shop/owned` when its tab
  is shown again, and on start.

## 5. Granting (save)
- `S.shop = { owned: [], claimed: [], tools: { robo: true, sprinkler: true, bowl: true } }` added in `migrate()`.
- Cash items: on `GET /shop/owned`, each purchase id not in `S.shop.claimed` is granted once (items added to the owned lists, coin packs and
  the Supporter 2,000 coins added to `S.coins`, Gerald's letter posted), then its id goes into `claimed`. A new device that restores gets the
  items, and coin packs it has not claimed in this save (the cloud save carries `claimed`, so a synced save does not get coins twice).
- Refunded purchases: one-time items are taken back (worn items go back to "Nothing"); coins already granted are not taken back.
- Perks read `owns('shop', 'supporter')`, so a refund ends them.
- Coin buys of shop items write the same owned lists, no Worker call.
