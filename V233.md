# v2.33 "Helping paws" (contract; not built, not released)

Owner's choice, 23 Nov 2026: more interaction between players. Friends help each other on a yard visit (fill the bowl, water the garden,
make a wish come true, say thanks) and send a dog for a sleepover. Built on `claude/v233-helping-paws` (from `main`, v2.32.1).
A content release: it goes to `main` only with the owner's go-ahead and launch date (CLAUDE.md, the special-update rule).
Code: `game/src/60_helps.js` (tag `hp`, test hook `window.__paw.hp`: gate, save, helps, letters, stickers), `game/src/60b_sleep.js` (tag `sl`, the
sleepover), `game/css/63_helps.css`; small hooks in the files named in section 12. Worker: `cloudflare/worker.js` + `cloudflare/schema.sql` (one new
table, no `addcol`). Suites: `v233_helps` (game, cloud mock), `v233_worker` (Worker on a local D1). Save stays `v: 1`.

## 0. Rules that stay (V219.md 0)

No typed text leaves the device (friend names are word indices, dogs are Dog Card dogs, notes are `FR_NOTES` indices); the user id never leaves the
Worker; nothing personal is shown (no times beyond "today"); nobody loses anything to a friend, and my dog is never missing from my own game; remove
and block stay quiet; additive migration; phones first (360x640 and 390x844, 44 px taps, nothing under the phone bar). **No new coins**: this release
gives Bond, a diary page, a picture and stickers only (the one exception is the wish's own reward, 3.3). Nothing toxic: every treat is a `FOOD` row.
Words: never "breed" as a verb, "stud", "sell" for dogs. English through `tt('hp.*')`, translated once at the end (section 11).

## 1. Gates and older copies

- **Game:** `HP_FROM` in `60_helps.js`: `''` = no launch date (off), `'YYYY-MM-DD'` = on from 00:00 JST. `NEWS_V233.date` is the same text (the suite
  fails when they differ). `hpOn()` = `frOn()` and ((not webdriver and `HP_FROM` due) or `prefs.hpTest`) **and** `FR.hp` (below). While off: no strip,
  no Sleepover button or menu row, no `hp` snapshot field, no `?hp=1`, no `S.hp` writes beyond the migration defaults.
- **Server capability:** `GET /friends` answers a top-level `hp: 1` once the Worker's gate is open. `frLoad` sets `FR.hp = r.data.hp === 1` (memory only,
  false on every load until the first answer). An older Worker never sends it, so the client stays exactly v2.32.1 with it.
- **Worker gate:** `HP_FROM` in `worker.js` (the same date at 00:00 JST **less 10 minutes**; the env variable `HP_FROM` = ms, ISO, `0` open, `off` shut,
  as `BT_FROM`). Shut: no `hp` in `GET /friends`, the new kinds and the snapshot's `hp` answer `400 bad`, note 12 is `400 bad`, `?hp=1` and `acts`
  are ignored/refused exactly as by the v2.32 Worker. `v233_worker` fails when the Worker's date and `HP_FROM` in the game differ.
- **A rolled-back Worker** (the game saw `hp: 1`, then a send answers `400 bad` for a new kind): `FR.hp = false` for the rest of the load, the toast
  `hp.failed`, nothing taken from the bag, no Bond. Offline or 5xx: `fr.offline` toast, nothing changes (every effect waits for `{ ok: true }`).
- **Older game copies (v2.32.1, cached tabs) on the new Worker:** they never ask `?hp=1`, so they never see the new kinds; `GET /friends/inbox`
  without `?hp=1` also leaves out notes with `i >= 12` (their `FR_NOTES` has 12, they would sit on the badge); extra fields in `GET /friends`
  (`hp`, `sent.bowl` ...) and in a snapshot (`hp`) are ignored by `frLoad`, `frSentN` and `frYardClean`. Helps and sleepovers sent to a friend
  on an old copy wait in the Worker (30 days, as all events) until that friend updates.

## 2. Server (`cloudflare/worker.js`, `cloudflare/schema.sql`)

**Why a new table:** `friend_events.kind` has `check (kind in ('pet','note','gift','walk'))`; D1/SQLite cannot change a CHECK without rebuilding the
table. So, additive:

```
create table if not exists friend_acts (            -- v2.33 helps and sleepovers. No CHECK on kind: the Worker validates (HP_KINDS), so a later
  id integer primary key autoincrement,             -- kind needs no new table. claimed_at null until the claim. Deleted like friend_events.
  to_id text not null, from_id text not null, kind text not null, data text not null,
  day text not null, created_at integer not null, claimed_at integer);
create unique index if not exists friend_acts_pair  on friend_acts (from_id, to_id, kind, day) where kind != 'sleep';
create unique index if not exists friend_acts_sleep on friend_acts (from_id, kind, day) where kind = 'sleep';
create index if not exists friend_acts_inbox on friend_acts (to_id, claimed_at);
create index if not exists friend_acts_age on friend_acts (created_at);
```

Constants: `HP_KINDS = ['bowl','water','wish','sleep']`; `HP_LIM = { wish: 13 }` (length of `HP_WISH`, 3.3); `HP_WISH_DO = [0, 1, 2]` (the wish
kinds a visitor can do: pet, ball, snack; a later doable kind is appended to `HP_WISH` and added here); `FR_LIM.notes` **12 -> 13** (open gate only);
`FR_NOTES_OLD = 12`. Days are Japan days (`dcDay`). No new rate-limit buckets.

| Route | v2.33 change (gate open) | Limit |
| --- | --- | --- |
| `GET /friends` | top-level `hp: 1`; each row's `sent` adds `bowl, water, wish, sleep` (booleans, today, from `friend_acts` where `from_id` = me) | 120/h |
| `POST /friends/send` | `kind` may also be `bowl`/`water` (data `{}` or absent, like pet), `wish` (exactly `{ w }` or `{ w, a }`: `w` in `HP_WISH_DO`; `a` only with `w = 2`, an `FR_GIFTS` index), `sleep` (exactly `{ dog }`, a Dog Card dog checked with `dcDog`). `note` takes `i` 0..12. Help kinds: once per (from, to, kind, Japan day); `sleep`: once per (from, Japan day) to anyone; a repeat is `400 limit` (pre-check + the unique index, as today). Friends only, block = `404 not_found`. **To an official account** (`frIsOfficial`): the row is written with `claimed_at = now` (the limits hold, nothing is delivered, the inbox sweep deletes it; the official yard is everyone's and must not drown). Answer `{ ok: true }` | 60/h, the existing `fr:send` bucket |
| `PUT /friends/yard` | optional `hp: { d, g, w?, a? }`: `d` a `YYYY-MM-DD`, `g` int 0..6 (growing plots), `w` int 0..12 (`HP_WISH`), `a` only with `w = 2`, an `FR_GIFTS` index. Any other key in `hp`: `400 bad`. Stored and returned by `GET /friends/yard` | 30/h |
| `GET /friends/inbox` | with `?hp=1`: `{ events, acts, hp: 1 }`; `acts` = my unclaimed `friend_acts`, `order by (kind = 'sleep') asc, id asc limit 30`, each `{ id, from: { fid, name }, kind, data, day }` (from `friend_ids`, never a user id). | `POST /friends/inbox/claim` | body `{ ids, acts? }` (`frOnly(body, ['ids'], ['acts'])`), `acts` at most 30 ints, claimed `where to_id = me` like `ids` | 120/h |
| `POST /friends/remove`, `/block` | `frUnlink` also deletes **unclaimed** `friend_acts` between the two (both ways) | as today |
| `POST /friends/leave` | also deletes my `friend_acts`, sent and received | as today |
| `frTidy` | also deletes `friend_acts` rows whose `from_id` or `to_id` is gone | as today |

The snapshot stays strict (unknown keys are `400 bad`, as for v2.30's outfits), so the game sends `hp` only with `FR.hp`, and if a `PUT` with `hp`
answers `bad` it sends the same yard again without it (`FR.hpOld = true` for the load, next to `FR.decorOld` in `frAfterPush`).
Header comment block of `worker.js` lists the new shapes. Deploy: `tools/cf_api_deploy.sh` (the schema makes the table); the owner approves the prompt.

## 3. Part A: three helps on a yard visit (`cur.mode = 'fryard'`)

### 3.1 What the helper sees

- **The help strip** `#hpStrip` (HTML, under the place chip `#status`, where `#ddWish` sits at home): the word "Help out" and three round 44 px
  buttons: the bowl (`art('prop','bowl-empty')`), the watering can (the garden module's `water-can` drawing), the wish (`ICON('heart')`). Each: today
  not done = coloured; done today (`frSentToday(fid, kind)`, fed by the row's `sent`) = a tick and `hp.done_today` on tap. The can rests (greyed,
  `aria-disabled`) and says `hp.garden_rest` "The garden is resting." when the snapshot has no `hp`, `hp.d` is not today (JST) or `hp.g` is 0. The
  wish button shows only for a doable wish (3.3). Tapping a button pans the phone camera to the spot (`frCamTo`, 0.5 s) and plays the help there.
  The same props in the scene are tappable too. `frScan` adds `#hpStrip` to its boxes and `#hpG [data-hp]` to its feet, so no dog stands on them.
- **Bowl** (always offered): drawn in `#hpG` (a group after `#frStampG`) at `HP_BOWL = [548, 474, 76, 76]` (beside the house's left corner; the phone
  check may move it, inside the 360 and 390 crops, clear of `FR_STAMP` and the greeting pair) with `bowlArt(null)`. Tap: the scoop (new art) tips
  over it, three kibble dots fall (0.9 s), the bowl becomes `bowlArt('Basic Kibble')`, two hearts over their leader, `SFX.crunch` then `SFX.boop`.
- **Water the garden**: only when the snapshot says something is growing today: the scene is drawn with `patch: 'growing'` (not `'empty'`) and the
  can stands at `HP_CAN = [150, 388, 56, 56]` on the veggie patch's top edge. Tap: the can tilts, four drops fall (1 s), `sfx('water')`.
- **The wish**: their leader (`FRV.dogs` first friend dog) gets a thought bubble in the `#ddWish` look (`.dd-wish` classes, the tail pointing down),
  anchored over its head with the screen CTM and moved by the frame loop: "Today I wish for {wish}" (`ddWishText(k, food name)`). Doable kinds
  have the strip button and a tappable bubble; others show the bubble only, a tap says `hp.wish_home` "That wish is one for home.".
  - pet: the pet animation (`frPetDog`), then the send; the normal `pet` event goes too if it was not sent today.
  - ball: `ICON('ball')` arcs from my leader to theirs (0.8 s), their leader `jump` then `happy`, `SFX.squeak`.
  - snack: a sheet like the gift sheet (`.fr-giftgrid`): my bag's `FR_GIFTS` rows with `frGiftRef(i).cat === 'food'`, only the named food when the
    wish names one; none: `hp.snack_none` / `hp.snack_empty`. Confirm `hp.snack_ask` "Give 1 {food} to {dog}?". One leaves my bag (`frGiftTake`) only
    after `{ ok: true }`; their leader eats (`happy`, `SFX.crunch`). It is not the day's gift (`S.fr.gift` untouched).
- **After `{ ok: true }`**: `frMarkSent(fid, kind)`, `S.hp.n++`, and +1 Bond to my leader while `S.hp.bond < 5` (`HP_BOND_MAX`, its own count, not the
  pet cap): toast `hp.helped` "{dog} helped out! +1 Bond" (no Bond part at the cap). `limit`: mark done quietly. A friend with no snapshot: no visit
  (as today), so no helps.
- **Reduced motion** (`motionOff()`): no scoop, can tilt, drops or ball arc; the bowl just fills, the dog just turns `happy`, one heart each.

### 3.2 What the friend gets (claim)

`frInbox` asks `GET /friends/inbox?hp=1` while `hpOn()`; `acts` go to `hpActs(acts, claimActs)` (`60_helps.js`), whose ids are claimed with
`{ ids, acts }` only when there are some. An act id already in `S.hp.ids` (last 90) is only claimed again, never applied twice.
- **One letter per helper per Japan day**: id `hp_help_<day>_<fid>` (`kind: 'postcard'`, `frPaw: true`, `hpHelp: { fid, who, day, ks: [], ids: [] }`),
  built like `frPetLetter`: a later read that day adds the new helps to it and marks it unread. Title `hp.l_title` "{who} helped out!", text
  `hp.l_text` "{who} stopped by: {list}." with `tlist` of `hp.l_bowl` "filled {dog}'s bowl", `hp.l_water` "watered the garden", `hp.l_wish` "made {dog}'s
  wish come true" (e.g. "Sunny Biscuit stopped by: filled Pip's bowl and watered the garden."), the effects in `m.ps`.
- **The leader** is my snapshot's leader (`dogById(S.fr.snap[0])`, else `D()`).
- **bowl**: +20 Hunger to the leader (`withDog(d, () => addStat('hunger', 20))`, clamped at 100), at most 3 a day (`S.hp.bowls`); more: the letter only.
- **water**: when the garden is open (`gkOn()`, `gardenUnlocked()`): `gardenAdvance()`, then every plot with a crop and `g < 1` gets `water = 3, wd = 0`
  (a full can, as `PawGarden.water`; about 3 hours of growing on a sunny day), `gardenCtl.update`. Nothing growing: the letter only.
- **wish** (`data.w`, `data.a`): granted with its normal reward (`ddWishDone(d, w)`: double Bond, the wish count, stickers, and its usual wish coins
  inside `DD_COIN_DAY`; no new coin source) **only if** `ev.day === jstISO()`, the leader's current wish is not done, `HP_WISH[data.w] === w.k`, and for a
  snack `FR_GIFTS[data.a] === w.a` when `w.a` is set. Otherwise (already granted, a new day, a different wish): the kind letter and +1 Bond to the
  leader while `S.hp.gotB < 5`, `m.ps` `hp.l_ps_bond`.
- **Say thanks** on the letter (`hpLetterAct(m)` in the letter's action row): sends note **12** "Thank you for helping!" to `m.hpHelp.fid`. It uses that
  day's note for that friend: after a note today it reads `hp.thanked` "Thanked today" (`aria-disabled`); ok: `frMarkSent(fid,'note')`, toast
  `hp.thanks_ok`; `404`: `fr.not_friend`. The friend receives the usual paw-print postcard; `frInbox` counts note 12 in `S.hp.thx`.

## 5. Save (`v233Fields(s)`, additive; from `freshState` and `migrate()` like `fiFields`)

```
S.hp = { day: '' (JST day of the counters), bond: 0 (helper Bond today, max 5), gotB: 0 (wish-already-granted Bond today, max 5),
         bowls: 0 (bowl top-ups claimed today, max 3), n: 0 (helps given, ever), thx: 0 (thank-you notes received, ever),
         host: 0 (guests hosted, ever), ids: [] (act ids applied, last 90), slDay: '' (the JST day of my sleepover),
         sl: [] (my sleepover recipes, last 10), gu: [] (today's guests, at most 2) }
```
Daily counters reset on a new JST day (`hpDay()`, from `frDay`). Wrong types get defaults; arrays are cut to their caps. Cloud sync carries `S.hp`.
None of it goes into the snapshot except the computed `hp` field (2).

## Changes from the brief

- New kinds go in a **new table `friend_acts`**, not `friend_events`: its CHECK constraint on `kind` cannot change without a table rebuild.
- The inbox gives them as **`acts` only to `?hp=1`**, claimed with `acts`: an old copy can never see or claim them.
- The snapshot's **unknown fields are refused today, not dropped** (`dcKeys` is exact): `hp` is sent only after `hp: 1`, and resent without on `bad`.
- **Notes from 12 on are hidden from old copies** (they would sit unclaimed on the badge), so "Say thanks" works on mixed versions.
- The wish's **day check** is "the friend's current wish is still that kind and not done, on the same JST day": wishes run on the device day.
- A friend-granted wish keeps **its usual wish coins** (inside `DD_COIN_DAY`): otherwise the friend would lose them; no new coin source.
- The helps are a **strip under the chip plus scene taps**, not three more bottom buttons (four would not fit at 360 with the bowl and can taps).
- The bowl stands **beside the house**, not at the home bowl spot (x 205-295, likely outside the visit's phone crop, which rests on the house); its coordinates are for the phone check to confirm.
- **Helps and sleepovers to the official account** are stored as already claimed (limits hold, its owner is not flooded).
- The stickers are a **full 6-sticker page** (3 helper + first sleepover + first guest + first thanks), so the page and its gift work as every page.
