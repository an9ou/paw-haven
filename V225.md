Owner-approved release (11 Nov 2026). Design: `docs/design/improvement-plan.md`, release A; `docs/design/retention-ideas.md` items 1, 4, 5, 6.
Code: `game/src/53_welcome.js` (tag `wb`, hook `window.__paw.wb`), `game/css/56_welcome.css`. Suite: `v225_welcome`.
Small hooks elsewhere: `applyAway()` (`21_time_loop.js`), `mbGrant` / `mbGiftLabel` (`07b_mailbox.js`, a letter gift may carry `bag`),

Under 4 hours the old "napped for N game hours" toast stays |

Art: no new art. The plan's "yard flag" and "golden bowl" have no art yet: the 30-day gift is an existing decoration and the 365-day gift is the

Order on a calm yard: the calendar's daily page, then the What's new sheet, then the While you were out page (`nwCalmNow()` plus 2.5 calm s).
Under the test harness everything except the day count needs `prefs.wbTest`.

## 2. Save fields (additive in `migrate()` and `freshState()`; `v` stays 1)

| Field | Default (old save) | Meaning |
| --- | --- | --- |
| `daysPlayed` | inferred, see below | distinct Japan days played |
| `daysLastISO` | `''` (or today if a record proves today) | the last Japan date counted; a date not later than it never counts (a clock turned back) |
| `daysGifts` | `[]` | milestones given (7, 30, 100, 365) |
| `lastSeenAt` | `0` (new save: now) | ms, a high-water mark of "now" at each return: away = now - max(`lastReal`, `lastSeenAt`), so a clock moved forward and back brings no second page or letter |
| `awayGiftISO` | `''` | the Japan date of the last away gift |
| `backISO` | `''` | the Japan date of the last welcome-back letter |
| `tmrwISO` | `''` | the Japan date of the last tomorrow line |
| `wbPend` | `null` | `{ at, h }` a page still to show (kept across a reload) |

Old saves' `daysPlayed`: the most any record proves, never a guess upwards: distinct dates of the diary pages (`S.dd.diary`, `j` or `d`) and
the welcome week (`S.fw.wel.days`), this month's calendar paws (`S.fw.cal.days`), Gerald's pouches (`S.missions.pouch.c`, one a Japan day).
A save already past a milestone gets that gift on its first day (nothing is held back).

## 3. Numbers

`WB_AWAY_MS` 4 h, `WB_BACK_MS` 3 days, `WB_COIN_CAP` 30, `WB_BACK_COINS` 100, `WB_DAYS` [7, 30, 100, 365]. Economy: the away gift is about
3 coins a day on average (coins on ~12% of days), the welcome-back letter only after 3+ days away: well below walks (~100 a day).

## 4. Tests (`node game/run_tests.js v225_welcome`)

1. Migration: the defaults, the honest day count (diary + welcome week dates, calendar paws, pouches, no future dates), existing fields kept;
   a real old save through Continue keeps every field and `v: 1`.
2. The page: 1 h away = toast, no page; 5 h = the page on a calm yard (2 lines with the name, the head, "away for 5 hours", the gift, "Hello, <name>!");
   12+ h = 3 lines, stable per return; a second long absence the same day: no second gift; a pending page survives a reload; it waits for What's new.
3. The gift: 365 dates: coins rare, 10-30; treats dog-safe; once a Japan day; a later stamped date gives none.
4. The letter: 2 days = none; 3+ days = one, 100 coins + a treat bag, once that day; clock forward-and-back = nothing; Collect pays once.
5. Days played: distinct Japan days, the same day and a clock turned back add nothing; 7 / 30 / 100 / 365 gifts once each with a kept letter;
   the frames in photo mode; the calendar line.
6. The tomorrow line: not before the pouch; once after it; not again that day; the crop line.
7. Fit: phone 360x640 and desktop 1280x720, the sheet inside the screen, a 44 px button, no text overflow (screenshots `v225_welcome_<size>.png`).
