| `id` | Bahasa Indonesia | Indonesian | other | no plural inflection |

`many` (fr/es/pt for a million) falls back to `other`, so a translation needs only `one` and `other`. ja/zh/ko/th/id need only `other` (an `=0` or `=1` branch still works).

**`pickLang(list)`** (in `msg.js`, shared by the game and the site): the first entry of `navigator.languages` (or one tag, or a saved code) that maps wins, else `'en'`. Case and `_` do not matter.
- `zh-TW`, `zh-HK`, `zh-MO`, `zh-Hant(-*)` → `zh-Hant`; `zh`, `zh-CN`, `zh-SG`, `zh-MY`, `zh-Hans(-*)` → `zh-Hans`
- `pt(-*)` → `pt-BR`; `es(-*)` → `es`; `in` (old Java code) → `id`
- any other: the base subtag (`ja-JP` → `ja`, `fr-CA` → `fr`); nothing matches (`nl`, `sv`, `it`) → try the next entry → `en`.

## 3. Messages (`game/i18n/msg.js`)

### 3.1 Syntax: an ICU MessageFormat subset, nothing else

| Form | Meaning |
|---|---|
| `{name}` | the var as a string. Numbers are **not** grouped here (a year stays `2026`): pass `tnum(n)` when grouping is wanted. |
| `{n, plural, =0 {no dogs} one {# dog} other {# dogs}}` | `=N` first, then the `Intl.PluralRules(lang)` category, then `other`. `#` = `n` through `Intl.NumberFormat(lang)` (the innermost plural). |
| `{x, select, female {..} male {..} other {..}}` | the var as a string, then `other` |
| `{name, josa, 이/가}` | Korean particles (3.2) |

Branches nest. Every plural and select needs `other`. Apostrophes are plain text (no ICU quoting), so `It's {name}'s ball` is fine; `{` and `}` are always syntax. A missing var renders as `{name}` so tests can see it. `format()` never throws (a broken message comes back as written); `parse()` throws and is what the tests use.

API: `format(msg, vars, lang)`, `parse(msg)`, `args(msg)` → `{ name: 'arg'|'plural'|'select'|'josa' }`, `pickLang(list)`, `LANGS`, `LANG_EN`, `CODES` (picker order: en, ja, zh-Hans, zh-Hant, ko, es, pt-BR, fr, de, th, id), `pluralCat(n, lang)`, `num(n, lang, opts)`, `date(d, lang, opts)`, `list(arr, lang)` (`Intl.ListFormat`, "A, B and C"), `lookup(table, en, key, vars, lang)`, `id(s)`, `josa(word, a, b)`, `JOSA`. Parsed messages and Intl objects are cached.

### 3.2 Korean particles (Coordinator's call, 18 Oct)

After a var, Korean must not hard-code 이/가, 을/를, 은/는, 와/과, (으)로. `{name, josa, 이/가}` prints the var plus the particle for its last syllable: a final consonant (batchim) takes the first form, a vowel the second; for `으로/로` a vowel **or ㄹ** takes 로. Digits count as read in Sino-Korean (3 삼 → 을, 2 이 → 를). Anything else (a Latin name like "Mochi") gets the both-forms spelling: `Mochi이(가)`, `Mochi(으)로`. Pairs (with-batchim form first): `이/가 을/를 은/는 과/와 아/야 이랑/랑 으로/로 이에요/예요 이었/였`; any other pair is a parse error. Translators may also rephrase so no particle follows a var (e.g. `{name}: …`, `{name} 씨`-free noun phrases). See `docs/i18n/ko.md` section 2.

### 3.3 Rewriting sentences into messages (phase 2 wiring lanes)

The extractor marks 194 `concat` hits (sentences built with `+`) and 186 hits with a `${a ? 'x' : 'y'}` inside (`cond`). Rules:
1. **One message per sentence, never glued pieces.** `'Back to ' + n` → `tt('toys.back_to', 'Back to {place}', { place })`. A message may hold several sentences when they always go together.
2. **Conditions become `select` or two keys**, with whole sentences in each branch: `` `It's raining.${hasRaincoat() ? ' Good thing about that raincoat.' : ' Expect mud.'}` `` → `{coat, select, yes {It's raining. Good thing about that raincoat.} other {It's raining. Expect mud.}}`.
3. **Pronouns are never vars.** Pass `sex: 'female'|'male'` (the dog's own `sex` value) and select whole sentences: `{He} has never said that` → `{sex, select, female {She has never said that} other {He has never said that}}`. Other languages inflect verbs and adjectives too.
4. **Number + noun is a plural**, even in English (`{n, plural, one {# coin} other {# coins}}`).
5. **Lists** go through `tlist(names)`, never `', '` and `' and '`.
6. **Word order belongs to the translator**: name every var (`{name}`, `{place}`, `{item}`, `{n}`), never `{v}` / `{v2}`. Breed, item and place names arrive already translated (`tbreed`, `tdata`).
7. **HTML**: keys ending in `_html` may hold `<b>`, `<i>`, `<br>` and `<span class="…">` only, and `tt` escapes their var values itself. Every other message is plain text (no `<`), and callers `esc()` it as they do today.

## 4. String tables: files, keys, the build

### 4.1 Inline English, generated en.json

**Decision (SPEC):** the English stays in the code, next to its key: `tt('walk.home_early', 'Head home early')`. Why:
- It needs no shared `en.json` edits while seven wiring lanes run (no merge conflicts on one big file).
- The code stays readable, the `copy` suite keeps checking the English where it is written, and the per-key English fallback is automatic.
- The English is not shipped twice.

`game/i18n/en.json` is **generated** by `node tools/i18n_extract.js --en` (phase 2 adds the mode). It holds every `tt()` key with its English, plus every data string named in `game/i18n/TABLES.txt` (4.3). If one key has two different English texts, it is an error. Translators read `en.json` and write `game/i18n/<lang>.json`: flat keys, string values, a subset of `en.json`'s keys. A missing or empty value means the English is used.

**Key names:** `<area>.<what>`, lowercase `a-z0-9_`. The parts are joined by dots. Areas follow the files (the extractor's `AREA` map): `core title adopt yard bath shop wardrobe journal mail map walk genes garden popup pack playdate puppies town vet train tricks idle pupplay route toys fetch settings time input cloud reset phone missions guide fest hw home care shelter winter newyear japan packplay photo pers roam ball tokyo cards boot`, `shell.*` for `shell.html`, `mod.<module>.*` for `mods/`, `art.*` for aria-labels in art, `data.<table>.<path>` for data tables. Examples: `walk.home_early`, `yard.zoomies_imminent`, `shop.buy_html`, `data.food.basic_kibble.note`. A key never changes once translated; a changed English sentence keeps its key unless the meaning changes.

### 4.2 Shared-scope helpers (`game/src/00b_i18n.js`, new in phase 2, right after `00_core.js` in `ORDER.txt`)

**Why not `t()`:** a local `t` is bound **161 times** in `game/src` (`(t) =>`, `const t =`), and `tn` twice. Any `t('…')` call inside those scopes would silently call the local. The `i18n` suite fails if any of the names below is bound anywhere outside `00b_i18n.js`.

| Name | What |
|---|---|
| `tt(key, en, vars)` | the message for `key` in the current language, else `en`, formatted with `vars` (`PawI18nMsg.lookup`). Records a miss in `__paw.i18n.misses` when the language is not `en`. |
| `tdata(path, en, vars)` | data text: key `'data.' + path`, e.g. `tdata('food.' + tid(f.n) + '.note', f.note)` |
| `tid(s)` | `PawI18nMsg.id`: `'Bone-shaped Biscuit'` → `bone_shaped_biscuit` |
| `tbreed(key)` | the breed name shown (`data.breed_names.<key>`, filled from the glossary `breeds`) |
| `tnum(n, opts)` / `tdate(d, opts)` / `tlist(arr)` | `Intl` formats in the current language (section 8) |
| `tlang()` | the current code |
| `tsetLang(code)` | switch (section 5) |
| `__paw.i18n` | test hook `{ lang, misses, set }` |

`window.PawI18n = { tt, tdata, tbreed, tnum, tlang }` is set when `00b` loads. Modules (`mods/*.js`) call it **only at run time, inside functions**, through a local `L(key, en, vars)`: `root.PawI18n ? root.PawI18n.tt(key, en, vars) : fmt(en, vars)`. Here `fmt` is `PawI18nMsg.format` when present (node tests can `require('../game/i18n/msg.js')`), else the English. Modules still never touch game state or storage: the language service is read-only.

### 4.3 Data tables: English is the data, display text is looked up by id

Never rename a table key, an item name or a save value. `S.inv.food['Wild Berries']`, `S.outfit.body === 'Mossy Poncho'` and `DC_OUTFITS.indexOf(o)` keep working. Only the **display** goes through `tdata`.
- Path rule, the same one the extractor's `dataPath` uses:
  - an object row with `id`/`key`/`k`/`n`/`name`: `<table>.<tid(id)>.<field>` (`food.wild_berries.note`, `hm_decor.bird_bath.story`)
  - a map: `<table>.<prop>.<prop>` (`place_lines.golden.market`)
  - a plain array: the index (`dc_words_a.12`). It is stable because these lists are append only.
  - an array row that starts with key words: those words joined with `_` (`mix_list.westie_yorkie.2`)
- `game/i18n/TABLES.txt` (phase 2, I18N CORE) lists which tables and fields are text: one line per table, `FOOD n note tip`, `PLACE_LINES *`, and so on. `--en` takes exactly those strings, so no heuristics go into `en.json`.
- Tables (extractor counts): `MIX_LIST` 560, toys `LINES` 415, `WX_LINES` 232, genes `WORDS` 230, `PLACE_LINES` 210, `TK_LINES` 210, `JOKES` 194, `FALLBACK_DOGS` 140, `SIG_COMBO` 105, `CLOTHES` 88, `FOOD` 86, `TREASURES` 76, `BREED_PERS` 74, `MS_POOL` 72, `DC_OUTFITS` 50, `DC_WORDS_A/B` 39/40, `BREED_NAMES` 35, `HM_DECOR` 34, `BD_TIPS` 23, `GD_LESSONS` 16, and about 150 small ones.
- **The two-sentence lessons** (`FOOD` `tip`, `BD_TIPS`, the kitchen unsafe notes, `GD_LESSONS`, the seasonal care notes) stay short, kind and two sentences in every language. th has no sentence periods, so the test counts sentence ends only for the other languages (13).
- **Breed names**: from the glossary `breeds` (35 keys, checked). Breed words inside sentences are `{breed}` vars.
- **Mix names** (561 named mixes and "Mutt mix"):
  - es, pt-BR, fr, de and id keep the English pun names, which are used as-is in those markets (Labradoodle, Maltipoo), unless the glossary gives a local one.
  - ja, zh-Hans, zh-Hant, ko and th translate the well-known real ones and use the pattern `genes.mix_pattern` (`{a}×{b}` style, per language) for the made-up puns.
  - `mixName()` returns the table entry if present, else the pattern in those five languages, else the English.
- **Dog names never change.** Names the player typed, and every built-in dog name list, stay exactly as they are in every language. A name is stored on the dog, and Dog Cards match it by string (`dcOwnNameIdx`). The built-in lists are the starter names in `SP`, `FALLBACK_DOGS`, `PUP_NAMES`, `RESCUE_NAMES`, `SR_NAMES`, `DC_PET_NAMES` and `DC_FAKE`. **People's names** (Gerald, Mrs. Plum, `NPC_BOYS/GIRLS`, families) are display text only, so translators may transliterate them as glossary `terms`.
- **Dog Cards stay language-neutral.**
  - The Worker and D1 still store only list indices; the Worker is unchanged.
  - Each viewer sees the word for each index in their own language: `tdata('dc_words_a.' + i, DC_WORDS_A[i])`, the same for `dc_words_b`, `dc_outfits` and the breed-word part of `DC_DOG_NAMES` (`DC_BREED_WORDS`). `DC_PET_NAMES` are names and stay as they are.
  - The append-only index rule holds **per language**: a translated list never drops, reorders or merges an index.
  - The card name order is a message, `cards.name_pattern` = `{a} {b}` (fr/es/pt may write `{b} {a}`). Translators choose adjective forms that do not inflect for gender, or noun–noun pairs (TODO(native)).
- **Art**: the painted sign words in the art (`b.tx(…, 'DOG')`, 37 hits: KIBBLE, DOG, this way up) stay as drawn, as part of the sketchbook. Every old render stays byte-identical. Aria-labels in art come from the game: a module that builds its own label (the dog SVG "Mochi the Shiba") takes an optional `o.aria` from the game. Without it the old label is used, so `node dogs/check_identical.js` still passes.
- **The dev panel** (`20_settings_dev.js` dev part, itch strips it) stays English: about 67 strings.

### 4.4 Into the builds

The tables are packed by `node tools/i18n_pack.js` (phase 2, I18N CORE) into **`game/i18n/packed.js`**. Like `35b_photo_fonts.js`, it is generated, committed, and never edited by hand:
- `window.PAW_I18N = { v: 1, keys: [<every en.json key, sorted>], ja: [<text or null per key>], … }`, one array per language in `CODES` order, without `en` (the English is in the code). The keys are stored once, not 10 times.
- The runtime turns only the current language into a key → text map.

| Build | How |
|---|---|
| `game/shell.html` | a new `<script id="pawi18n">/*@@I18N@@*/</script>` **before** `pawart` and `pawmods` (so `PawI18nMsg` exists when everything else loads) |
| `game/build.js` | slot = `msg.js` + `'\n'` + `packed.js`, raw text; `JSON`/syntax check of `packed.js` in `check` mode; the banned-word check grows to the local franchise names (10) |
| `tools/build.pl` | the same two files joined the same way, raw. That keeps the Perl and Node builds byte-identical (no JSON handling in Perl). |
| `tools/artifact.js` | a ninth file `i18n.js` (the same text) and `<script src="i18n.js">` in place of the slot |
| `game/harness.js` | fills the slot for the tests |
| `tools/itch.js` | unchanged: it takes the publish build (open decision 16.1) |

The `i18n` suite checks that every one of these fills the slot once `build.js` does, and that `packed.js` matches the tables.

**Size** (measured with the extractor on `integration/v2.14`, 18 Oct): 6,484 unique strings, 36,077 words, 201,577 characters of English (≈ 228 KB as JSON text), keys ≈ 185 KB. Translated text in UTF-8 bytes per language, estimated against the English bytes:
- ja ×1.6, zh-Hans ×1.05, zh-Hant ×1.05, ko ×1.5, th ×2.6
- es ×1.2, pt-BR ×1.2, fr ×1.25, de ×1.3, id ×1.15
- Σ ≈ ×13.9, so ≈ 3.2 MB for the 10 tables

With the keys stored once, `packed.js` is ≈ **3.4 MB** raw (≈ 1.0 MB gzipped). With flat per-language JSON (keys repeated) it would be ≈ 5.0 MB. The publish build grows from **4.02 MB** (1.34 MB gzipped) to about **7.4 MB** (≈ 2.4 MB gzipped), before fonts (section 11). That is well under the 16 MB artifact file limit and itch.io's limits. The real number will be 10–20 % lower: dog-name lists, mix puns, the dev panel and painted art stay English, and the extractor over-counts a little.

## 5. Save field, picker, switching

| Field | Shape and default | Owner |
|---|---|---|
| `S.lang` | one of `CODES`, or `null` = follow the device. Added in `v214Fields` in `migrate()` (additive, never bump `v`). Old saves load with `null`. | I18N CORE |

- **Current language** = `S.lang` if set, else `pickLang(navigator.languages)` each load. The detection runs at first run before a save exists, so the title screen already shows in the device language. A pick is saved in `S.lang` and goes with the cloud save (the language follows the account; open decision 16.2).
- **The picker:**
  - In Settings: a row "Language" with a button showing the current native name. It opens a list of the 11 native names, each with its English name in small text (`LANG_EN`), plus "Use device language", which sets `S.lang = null`.
  - On the title screen at first run (no save yet): a small chip with a globe icon and the native name under the buttons. It is one tap, so a player who can't read the current language can still find it.
  - 44 px rows. The language names never translate.
- **Switching:**
  - On the title screen, `tsetLang` re-renders the title (`enterTitle()`) live.
  - In the game it sets `S.lang`, calls `saveNow()`, and reloads the page. Every screen, the dock, the modals and the modules' DOM rebuild from `S` on boot, so no stale English stays on screen and nothing is lost.
  - During a walk, a trick game, cooking or ball play, the picker is disabled with "You can change the language at home." (no lost walk).

- **The harness** pins `S.lang = 'en'` (a `prefs.lang` pin in `test_lib.js`, option `lang`, default `'en'`), so every existing suite is unchanged. A suite passes `lang: 'ja'`; one test passes Playwright `locale: 'zh-TW'` with `lang: null` to check auto-detect.

## 7. Phone and desktop layout per language

New `game/css/50_i18n.css` (I18N CORE) plus per-lane phone rules, always under `html[lang|="xx"]`:
- **de, fr** (+25–35 % length; es/pt +25 %, id +20 %):
  - buttons, chips and tab labels wrap to two lines or shrink to the 15 px floor, never below
  - `overflow-wrap: anywhere` on narrow labels, and `hyphens: auto` (needs the `lang` attribute)
  - no fixed-width text boxes
- **ja, zh-Hans, zh-Hant**:
  - `line-break: strict` and `word-break: normal`, never `break-all`
  - no letter-spacing on CJK, a font stack with `'DD Local'` (11)
  - the text is narrower but taller, so check one-line chips for vertical clipping
- **ko**: `word-break: keep-all` with `overflow-wrap: anywhere` as the escape hatch.
- **th**:
  - `word-break: normal` (the browser breaks Thai by dictionary; never `break-all` or `keep-all`)
  - **line-height at least 1.5** everywhere Thai text sits, including one-line chips, the HUD, toasts and speech bubbles; Thai marks stack above and below
  - no `overflow: hidden` that clips them vertically
- The 44 px taps, the 15 px text floor and no sideways scroll hold in every language. The "Doodle Doggo" logo is the brand and is never translated; the subtitle is translated.

- **The Japan-date logic is unchanged.** `jstISO`, `HW_WIN`, `nyDays`, `todayKey` and every window keep comparing ISO strings; only the display changes.

## 11. Fonts (FONTS lane: `docs/i18n/FONTS.md`)

Reserved; FONTS.md is the contract. Interface fixed here:
- per language a subset `site/fonts/i18n/<lang>.woff2` + `<lang>.css` with the family **`'DD Local'`** (and `'DD Local Title'` if a heading face is used). It holds only the glyphs the tables need, so it is regenerated after translation.
- The game appends `'DD Local'` after the hand fonts in every stack, so Latin keeps Caveat, Patrick Hand and Gloria Hallelujah, and the missing glyphs (CJK, Hangul, Thai, any accent the hand fonts lack) fall to the subset. Only the current language's face is loaded, keyed by `html[lang]`.
- **The photo postcard**: `PH_FONT_CSS` (`35b_photo_fonts.js`, generated by `node tools/photo_fonts.js`) must carry the current language's `'DD Local'` too, because an SVG drawn to a canvas cannot load page fonts. How it is embedded (one data URI per language in the single file, or loaded at run time) and the size it adds are FONTS.md's call.

## 14. Extraction (`tools/i18n_extract.js`)

`node tools/i18n_extract.js [--out _i18n/extract.json] [--quiet]` (`_i18n/` is git-ignored). It reads `game/src` (concatenated in `ORDER.txt` order so the one IIFE parses; hits mapped back to file and line), `mods/*.js`, `game/shell.html` and, in `dogs/` and `world/`, only aria-labels, HTML text and painted sign words. It uses acorn from `npm root -g` (or eslint's or espree's copy) and installs nothing.

Hit kinds:
- `literal`
- `template` (with `vars`, plus `cond` when a `?:` sits inside)
- `concat` (a `+` sentence: rewrite)
- `data` (inside a `const UPPER = [..]/{..}` table, keyed `data.<table>.<path>`)

It drops ids, CSS, selectors, events, storage keys, URLs, SVG paths, keys, chord names and the class lists found in `game/css`, through small deny lists: calls such as `$`, `addEventListener`, `classList.*`, `clApi`, `itemArt`; comparisons, `case` labels, property keys and computed member keys. Sinks such as `toast`, `say`, `openModal`, `nope`, and `textContent`/`title` assignments mark text as shown. It never rewrites a file.
